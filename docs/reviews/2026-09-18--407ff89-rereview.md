## 剩余问题

### F1 · P2：非空说明文字或空代码块也能通过“有检查命令”的校验

位置：scripts/viktor-spawn.sh:99–105（尤其 105 行）。

问题：CHECKS 在添加运行前提之后只判断字符串非空。AGENTS.md 只有 `### 运行前提` 而没有 checks 块时，前提文字会使条件成立；只有空的 viktor-checks 围栏时也一样。--checks 文件同样只验证文件存在和最终文本非空。

复现：在临时仓库分别提供：

1. 只有 `### 运行前提` 和 `- 执行目录：.` 的 AGENTS.md。
2. 只有开始和结束围栏、没有任何命令的 viktor-checks 块。

两种情况下假的 claude 都被实际调用，并写出本轮 pass 报告，spawn 返回 0。此复现证明“无配置拒绝派单”的边界没有成立，不代表真实模型必然会报告 pass。

后果：直接调用、主会话漏传临时配置或不完整初始化时，子进程仍收到没有命令的配置，无法按主会话确定的执行入口工作。上一轮 R6 的自行推断提示已删除，但拒绝派单只完成了完全空文本这一种情况。

建议：把命令块和运行前提分开解析，派单前验证存在可用的已支持命令条目，且命令值非空；允许只有 verify 而没有 test，不强制所有检查键齐全。若要支持完全无命令的人工验收，应有显式模式，而不是靠非空说明文字绕过校验。覆盖 AGENTS 和 --checks 两条来源。

### F2 · P2：新增执行目录配置只影响提示词，hook 仍固定在 AGENTS 所在目录执行

位置：skills/viktor-init/SKILL.md:38–40、52–54；关联 hooks/viktor-gate.sh:13–14、48–51。

问题：init 现在要求在运行前提里填写“命令在哪个目录跑”，spawn 将其交给子进程；hook 并不读取该字段，仍在 AGENTS.md 所在目录运行命令。同时 init 第 52 行仍规定命令在 AGENTS 所在目录执行，产生两个相互冲突的目录约定。

复现：根目录 AGENTS.md 配置 `test: bash check.sh`，运行前提指定 `执行目录：server`；根目录和 server 中各有一个无副作用的测试脚本，记录实际工作目录。运行 hook 后退出码为 0，记录的是仓库根目录，而不是 server。

后果：子进程按前提验证 server 模块，hook 却运行根目录同名脚本并记录成功；若根目录没有脚本，则反复错误拦截。该问题来自新目录配置与现有 hook 的集成，hook 本次没有修改，不把它表述为 hook 自身的新增回归。

建议：选择唯一目录协议。最小修复是所有 checks 命令都要求可从 AGENTS 所在目录直接执行，子模块目录通过命令中的 cd 或构建工具参数表达，运行前提不得另行改变工作目录；另一种方案是让所有执行方统一解析目录，并将其纳入相应证据与缓存。不要同时保留两种解释。
