## 先探测自己有什么

你在一个独立进程里，能力取决于环境。开始前用一次探测确定：(a) 有没有浏览器工具；(b) 能否启动 dev server 并监听端口（沙箱可能不允许）。任一探测失败就放弃该路径——不重试、不换端口、不找替代方案——直接走下面的第 3 种方式。探测本身不超过 1 分钟。

## 验证方式（每条 AC 按能力选最高可得的一种）

1. 有 e2e 命令且已有覆盖该 AC 的用例：运行它。
2. 探测确认有浏览器工具且能起 dev server：启动后按 AC 描述实际操作，观察结果，必要时截图到 {{CHANGES_DIR}}/check/。用完关闭进程。
3. 其余情况：以能覆盖该 AC 的单元 / 集成测试作为证据（按 AC 名称过滤执行，例如 `npx vitest run -t 'AC-2'`）；渲染层面的表现标记 👀 待人工，写出精确的手动验证步骤（打开哪里、做什么、期望看到什么）。

不写新代码、不改实现、不跑 build、不安装依赖。AC 本身不可测或含糊，标 👀 并说明。检查命令无法执行（权限被拒等）时写 `result: error` 并说明原因后退出。
