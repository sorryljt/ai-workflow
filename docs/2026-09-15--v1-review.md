- [BLOCKING] **hooks/viktor-gate.sh:14 + skills/viktor-init/SKILL.md:24-29 —— 命令表解析很脆弱，误拦截和静默跳过都会发生。**
  - 实测 `read_cmd` 的行为：
    - 行尾 `|` 后有空格（`| test |  \`pnpm vitest run\`   |  `）：解析为空，**test 被静默跳过**。
    - CRLF 行（`| test | \`echo hi\` |\r`）：解析为空，**静默跳过**。`.gitattributes` 只约束本仓库，管不到业务项目。
    - 按 Markdown 规范转义的管道（`\`echo a \| grep a\``）：命令原样变成 `echo a \| grep a`，输出 `a | grep a`，**命令语义被改变**。
    - 三列表格（`| test | 命令 | 说明 |`）：解析结果为 `命令 | 说明`。
    - viktor-init 模板里的占位符 `…`，或 Agent 常写的 `无`、`-`：执行后分别得到 rc=127、127、2。**项目没有 typecheck 时，每次 Stop 都会被拦截。**
  - 后果：门禁时而拦住正常结束，时而悄悄失效，两种情况用户都看不到。
  - 建议：
    - 不再解析通用 Markdown 表格，改为在标记段外放一个机器可读块（例如 `<!-- viktor-checks` 下每行 `test=pnpm vitest run`），或者单独的 `.claude/viktor-checks.env`。
    - viktor-init 明确要求：命令缺失时整行省略；命令必须单行、非交互、非 watch 模式（例如 `vitest run`）。
    - install.test.sh 补上以上用例。

- [BLOCKING] **hooks/settings.snippet.json:8、hooks/viktor-gate.sh:7 —— hook 用相对路径，依赖当前 cwd，在 monorepo 或 cd 之后会静默失效。**
  - 官方文档（code.claude.com/docs/en/hooks）写明 "Handlers run in the current directory"，示例使用 `${CLAUDE_PROJECT_DIR}`。
  - 实测在子目录中：`bash .claude/hooks/viktor-gate.sh` 返回 `No such file or directory` rc=127，这是非阻塞错误，**门禁直接不生效**。换成绝对路径调用脚本，也会因为 `[[ -f AGENTS.md ]]` 不成立而 exit 0。
  - 后果：Agent 在 monorepo 子包里 `cd` 之后，门禁完全失效。

- [BLOCKING] **hooks/viktor-gate.sh:12 vs README.md:9 —— 门禁只拦一次，之后静默放行，与 README “失败则要求 Agent 修复后才能结束”不符。**

    - 允许重试 N 次（用状态文件计数，或直接依赖 8 次上限）。
    - 最终放行时，用用户可见的方式告知“检查仍失败”（例如 hook JSON 输出的用户可见消息字段，写入前以官方文档为准）。

### 新发现问题

- [BLOCKING] **B-1 hooks/viktor-gate.sh:10 —— `[[ -d "$ROOT/.git" ]]` 要求 `.git` 是目录，而 git worktree 中的 `.git` 是文件，门禁因此静默放行。**
